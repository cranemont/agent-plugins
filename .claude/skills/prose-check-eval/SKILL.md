# prose-check 모델 판정 측정

`pairs.mjs`는 `check.mjs`만 측정한다. 이 스킬은 모델이 SKILL.md 절차대로 검토한 결과를 측정한다. 모델은 `claude` CLI로 부르지 않고, 이 세션의 하위 에이전트로 돌린다.

## 절차

1. 글과 작업 목록을 만든다. Kiwi를 다른 데이터 폴더에 설치했으면 `PROSE_CHECK_HOME`을 붙인다. 에이전트의 Step 1 명령에도 같은 값이 들어간다.

   ```bash
   node scripts/prose-check/judge.mjs --prepare [--runs=3] [--seed=1]
   ```

   출력에 나온 `jobs.json`을 읽는다. 작업마다 `prompt`와 `report`가 있다.

2. 작업마다 하위 에이전트(general-purpose)를 하나씩 돌린다. 모든 작업을 한 응답에서 함께 시작한다.
   - 프롬프트는 `prompt`를 그대로 사용하고, 아무것도 더하지 않는다.
   - 에이전트에게 `key.json`, `pairs/style.tsv`, 이 측정의 목적을 알리지 않는다. 고친 문장이나 정답을 알면 측정이 무효다.
   - 사용자가 측정할 모델을 정했으면 에이전트의 모델로 지정한다. 정하지 않았으면 이 세션의 모델을 사용한다.

3. 모든 에이전트가 끝나면 `report` 파일이 모두 있는지 확인한다. 없는 작업만 다시 돌린다.

4. 채점한다. `--model`에는 에이전트가 사용한 모델 이름을 준다.

   ```bash
   node scripts/prose-check/judge.mjs --score <폴더> --model=<모델>
   node scripts/prose-check/judge.mjs --score <폴더> --model=<모델> --show   # 쌍마다 발견
   ```

5. `--show`로 고친 뒤 발견을 읽는다. 전문가가 고친 문장의 발견은 대개 오탐이다. 그러나 국립국어원이 고치지 않은 문제일 수도 있다. 오탐이 많은 규칙은 SKILL.md나 references의 설명을 고칠 후보다.

6. 사용자에게 보고한다. 탐지, 지적, 고친 뒤 발견의 실행별 값을 보인다. 스크립트가 놓친 쌍 가운데 모델이 찾은 쌍과 기준과의 차이도 보인다.

7. 사용자가 결과를 확인한 뒤에만 `--save`로 기준을 저장한다.

## 결과 읽는 법

| 값 | 뜻 |
|---|---|
| 탐지 | 고치기 전 문장에 기대한 규칙의 발견이 있다 |
| 지적 | 고치기 전 문장에 규칙과 상관없이 발견이 있다. 모델이 다른 규칙 태그로 같은 문제를 짚었을 수 있다 |
| 고친 뒤 발견 | 전문가가 고친 문장의 발견. 대개 오탐 |

- 모델 결과는 실행마다 다르다. 쌍 하나는 실행의 과반에서 찾았을 때만 찾은 것으로 센다. 기준과 1~2쌍 차이는 변동일 수 있다.
- 기준과 모델이 다르면 차이는 규칙보다 모델 때문일 수 있다.
- 실행 3번이면 에이전트 6개가 돈다. 에이전트마다 SKILL.md, references, 글 하나를 읽는다.
- `--prepare`는 작업 폴더를 데이터 폴더의 `judge/` 아래에 만들고, 측정이 끝나도 지우지 않는다. 필요 없으면 지운다.
