# 담백한 한국어 — 보고·문구·문서에서 장식 걷어내기

한국어 산문에서 장식을 걷어내고 확인 가능한 내용만 남기는 규칙. 적용 대상: 사용자 보고·UI 문구·코드 주석·커밋 메시지·저장소 문서·이슈와 PR 설명. 문구 파일(i18n·locale·messages)이 있으면 UI 문구는 거기다. 없으면 사용자에게 그대로 보이는 문자열이 놓인 자리를 본다 — 템플릿·CLI 도움말·로그·예외 메시지.
아래 규칙은 "쓰지 마라 → 대신 이렇게" 형태다. 5절(남길 것)이 과교정을 막는다.

**과교정 금지** — em dash, burstiness·perplexity 판정, `~를 통해`, `~것이다`, 문장 길이 다양화, 띄어쓰기 흐트러뜨리기는 손대지 않는다. 각 규칙의 근거와 이 목록의 계량 수치는 [references/research.md](references/research.md) — 규칙을 바꾸려면 근거를 먼저 반박한다.

**문체는 이 규칙이 정하지 않는다** — 종결어미와 높임은 대상(사용자 보고·커밋·문서)과 저장소의 기존 관례를 따른다. 아래 예시의 해라체는 문체 지시가 아니다. 저장소에 문체 규칙이 이미 있으면 그것이 먼저다.

## 1. 장엄체

- **발표형 도입** — "범인을 찾았습니다", "결론부터 말하면"으로 열지 않는다. 첫 문장에 파일·함수·조건을 적는다.
  - 나쁨: 드디어 원인을 잡았습니다.
  - 좋음: 원인은 `api/views.py:88`의 타임존 변환이다. `to_local`이 두 번 걸린다.
- **중요성 격상 술어** — "급소다 / 핵심이다 / 결정적이다 / 치명적이다"를 지운다. 여기가 깨지면 무엇이 어떻게 되는지 쓴다.
  - 나쁨: 이 검사가 이 기능의 관건이다.
  - 좋음: 이 검사를 빼면 서명이 안 맞는 요청도 서버가 그대로 받아들인다.
- **동일성 강조** — "정확히 그 경우 / 바로 그것 / ~ 그 자체 / ~에 다름 아니다"를 지우고 "A는 B다"로 쓴다.
  - 나쁨: 이 버그는 회귀에 다름 아니다.
  - 좋음: 이 버그는 회귀다.
- **극적 배열** — 놀라운 것을 앞에 놓지 않는다. 순서 기준(심각도 / 파일 / 조사한 순서)을 첫 줄에 밝히고 그대로 간다.
  - 나쁨: 가장 극적인 것부터 말씀드리면, 표 필터 버그입니다.
  - 좋음: 심각도 순이다. 데이터 손실 3건, 저장값 오류 2건, 표시 오류 4건.
- **반전용 단문** — 한 문장짜리 문단을 만들었으면 사실이 짧아서인지 효과를 노린 것인지 확인하고 후자면 앞 문단에 붙인다.
  - 나쁨: (앞 문단 뒤에 한 줄 띄우고) "그런데 문제가 하나 더 있었습니다."
  - 좋음: 압축 경로도 같은 값을 쓰므로 여기서도 같은 결과가 난다.
- **부정 대구** — "단순한 A가 아니라 B다 / A라기보다 B다"를 쓰지 않는다. B만 단언한다. 한 문서에 한 번을 넘기지 않는다.
  - 나쁨: 이것은 표시 오류가 아니라 저장 경로의 문제다.
  - 좋음: 저장 경로의 문제다.
- **마무리 요약·전망** — "정리하면", "이번 수정으로 ~할 수 있게 되었습니다", "앞으로 ~"로 닫지 않는다. 마지막 항목에서 끝내거나 못 고친 것을 적는다.
  - 나쁨: 정리하면 이번 수정으로 미리보기와 결과가 일치하게 되었습니다.
  - 좋음: 7번은 못 고쳤다. 재현 조건을 못 찾았다.

## 2. 유추·과장

- **의인화** — 화면·코드·저장소·데이터를 주어로 세우고 사람 동사(거짓말하다·말하다·알다·못 박다)를 붙이지 않는다. 기계적 동작(그린다·저장한다·던진다)은 그대로 써도 된다. 죽는 대상이 정해진 관용 표현(`프로세스가 죽는다`·`워커가 죽는다`·`커넥션이 끊긴다`)도 그대로 둔다 — 금지 대상은 화면·문서·코드가 사람처럼 구는 쪽이다.
  - 나쁨: 문서가 코드보다 먼저 낡아서 거짓말을 한다.
  - 좋음: `docs/architecture.md`에 적힌 경로와 실제 파일 위치가 어긋난다.
- **전투·수사물 어휘** — 범인·진범·급소·뇌관·사살·함정을 쓰지 않는다. "원인은 X"로 쓴다.
- **비유로 관계 묶기** — "~의 사촌 / 판박이 / 같은 부류"로 결론 내지 않는다. 파일·항목 번호를 대고 무엇이 같은지 한 문장으로 쓴다.
  - 나쁨: 이건 재시도 간격 문제의 사촌이다.
  - 좋음: `cmd/sync/retry.go`와 같은 규약이 걸린다 — 설정값과 실제 간격이 어긋난다.
- **비유 총량** — 결함 보고·작업 보고에는 비유를 0개로 둔다. 설계 문서(CLAUDE.md·AGENTS.md·ADR)에서는 문단당 최대 1개.
- **사실과 추측 분리** — 한 문장에 섞지 않는다. 추측에는 "확인하지 않음"을 붙여 따로 쓴다.
  - 나쁨: 아마 `src/image/pipeline.ts`의 반올림 때문에 크롭이 1px 밀리는 것으로 보입니다.
  - 좋음: 증상: 크롭 결과가 지정값보다 1px 작다. 추측: `src/image/pipeline.ts`의 반올림 — 확인하지 않았다.
- **심각도는 수치로** — "크다 / 심각하다 / 값어치 있다" 대신 개수·시간·영향 범위를 적는다. 범위를 넓힐 때도 몇 군데에서 재현되는지 센다.
  - 나쁨: 두 건은 보고된 것보다 훨씬 넓은 문제였다.
  - 좋음: 두 건은 같은 헬퍼를 쓰는 세 화면에서 재현된다 — `FilterMenu`·`SearchBar`·`Toolbar`. (화면·모듈 이름은 저장소의 실제 식별자로 쓴다. 일반 이름으로 바꾸면 받는 사람이 파일을 못 찾는다.)
- **평가 라벨로 목록 요약 금지** — "값이 컸던 것 / 의미 있는 발견"을 지운다. 그 항목이 공통으로 무엇을 하는지 적는다.

## 3. 서식

- **굵게**는 식별자(파일명·함수명·옵션명·UI 라벨)와 항목 머리말에만 쓴다. 형용사·부사·평가어에는 쓰지 않는다. 기울임으로 놀라움을 표시하지 않는다.
- **표**는 항목이 셋 이상이고 항목마다 비교할 값이 셋 이상일 때만 쓴다. `| 항목 | 설명 |` 두 칸 표는 문장으로 쓴다.
- **불릿**은 병렬 항목이 여럿일 때만. 한 문단으로 이어지는 서술을 쪼개 불릿으로 만들지 않는다.
- **삼항 나열** — 항목을 셋으로 맞추지 않는다. 둘이면 둘, 넷이면 넷. 박자를 채우려고 확인 안 된 항목을 넣지 않는다.
  - 나쁨: 이 변경은 빠르고, 안전하고, 되돌릴 수 있다.
  - 좋음: 되돌릴 수 있다. 속도와 안전성은 재지 않았다.

## 4. 한국어 문장

- **행위자 은폐 피동** — "밝혀졌습니다 / 확인되었습니다 / 요구됩니다"를 쓰지 않는다. 누가 무엇을 해서 알게 됐는지 능동으로 쓴다. (주어와 서술어가 호응하는 피동은 그대로 둬도 된다.)
  - 나쁨: 세 파일에서 같은 코드가 사용되는 것으로 확인되었습니다.
  - 좋음: grep으로 훑어 보니 세 파일이 같은 코드를 쓴다.
- **명사화** — 동사를 "진행하다·수행하다·실시하다·처리하다"로 바꾸지 않는다. 원래 동사를 그대로 쓴다.
  - 나쁨: 회귀 테스트 수행 후 배포 진행이 가능합니다.
  - 좋음: 회귀 테스트를 돌린 다음 배포하면 된다.
- **번역투 조사** — `~에 있어(서)`→`~에서`, `~에 있다`(단정)→`~이다`, `~에 대한`→`~의`, `~을 필요로 하다`→`~이 필요하다`, `~에 위치한`→`~에 있는`.
- **`-들`** — 붙이지 않는다. 수가 필요하면 숫자로 쓴다("세 곳").
- **강조 부사** — 정확히·완전히·통째로·전부·바로·실제로·매우를 지운다. 지워서 참·거짓이 안 변하면 원래 없어야 할 말이다. 정도를 말해야 하면 수치를 쓴다.
- **쉼표** — 연결어미(`~하면`, `~해서`, `~지만`) 뒤와 접속부사 뒤에 찍지 않는다. 한 문장에 쉼표가 둘 이상이면 문장을 쪼갠다.
- **`~인 것이다` 종결과 `우리 X`** — "것"을 지우고 `~이다`로 쓴다. 코드·기능은 "우리 편집기"가 아니라 `src/editor/`의 편집기로 부른다.

## 5. 남길 것 (담백함 ≠ 정보 줄이기)

지우는 대상은 장식이다. 다음 다섯 가지는 오히려 늘린다.

- 파일 경로·함수명·행 번호. "어딘가에서"가 아니라 `internal/store/session.go:142`.
- 수치. 몇 건, 몇 ms, 몇 kB, 몇 %. 심각도 형용사를 지운 자리를 이것으로 채운다.
- 재현 조건 한 줄. "~하면 ~가 보인다" 형태를 넣는다(`--dry-run` 없이 돌리면 exit code 0으로 끝난다).
- 확인 여부. 재현했는지 코드만 읽었는지 추측인지 밝힌다.
- 못 고친 것과 모르는 것. 제목은 짧게 쓰되 내용은 비우지 않는다 — `fix: 버그 수정`에는 무엇이 바뀌었는지가 없어서 나쁜 제목이다.

## 6. 표본 고쳐 쓰기

실제 보고에서 고친 문장이다. 화살표 왼쪽이 원문이고 오른쪽이 고친 것이다. 경로와 항목 번호는 형식을 보이려고 넣은 예시다. 쓸 때는 작업 중인 저장소의 값으로 바꾼다. 경로 예시에 파이썬·Go·타입스크립트를 섞어 둔 것도 자리표시자라는 표시다.

규약이 적힌 자리를 가리킬 때는 그 저장소가 쓰는 주소를 그대로 쓴다. 번호 매긴 목록이 있으면 번호를 대고 없으면 파일명과 제목(`AGENTS.md`의 "미리보기 딜레이" 항목)을 댄다. 둘 다 없으면 소스 경로를 댄다. 없는 번호를 지어내지 않는다.

1. "범인을 찾았습니다." → "원인은 `src/image/pipeline.ts`의 크기 계산이다."
2. "값이 컸던 자리들입니다." → "이 세 건은 사용자 데이터가 지워지는 경로다."
3. "이 저장소가 여러 번 못 박은 '미리보기와 결과가 같아야 한다'의 사촌입니다." → "같은 규칙이 `AGENTS.md`의 '미리보기 딜레이' 항목에 적혀 있다."
4. "우리 서버가 내려주는 응답이 정확히 그 경우입니다." → "`api/serializers.py`가 만드는 응답이 그 경우다."
5. "이번 과제가 없애려던 거짓말 그 자체입니다." → "이번 과제의 목표가 패널 표시와 산출물을 맞추는 것이었는데 이 결함이 둘을 다시 어긋나게 한다."
6. "이것이 이 프로토콜의 급소입니다." → "취소 뒤 늦게 도착한 청크가 다음 파일에 섞이면 받은 파일이 깨진다. 재현: 100MB 전송 중 취소 → 곧바로 다른 파일 전송."
7. "두 건은 보고된 결함보다 더 넓은 문제로 밝혀졌습니다." → "두 건은 보고된 조건 밖에서도 재현된다. 인증 헤더 없이 같은 경로를 부르면 같은 500이 난다."
8. "화면이 거짓말을 한다." → "패널은 1200×800으로 표시하는데 저장된 파일은 1199×800이다."
9. "값어치를 한 자리들입니다." → "고쳐서 재현 케이스 12건 중 11건이 통과했다."
10. "표는 필터를 걸면 커서가 걸러진 줄에 남아 *보이지도 않는 칸의 내용이 지워졌고*" → "표에 필터를 걸면 커서가 숨은 행에 남는다. 그 상태에서 Delete를 누르면 화면에 없는 칸이 지워진다."

## 7. 금지 표현 (문자열 그대로 검색해 잡는다)

활용형이 아니라 어간으로 적었다. `진행하`는 `진행합니다`·`진행했습니다`·`진행한다`를 함께 잡는다.

사촌 / 판박이 / 데자뷔 / 같은 부류 / 거짓말 / 값어치 / 값이 컸 / 의미 있는 발견 /
그 자체입니다 / 정확히 그 / 바로 그것 / 에 다름 아니 / 인 것입니다 / 인 것이다 /
밝혀졌 / 드러났 / 알고 보니 / 확인되었 / 요구됩니다 / 판단됩니다 /
드디어 / 마침내 / 놀랍게도 / 흥미롭게도 / 결론부터 /
단순한 ~가 아니라 / ~라기보다 / 정리하면 / 결론적으로 / 앞으로 ~할 수 있 /
우리 (뒤에 코드·파일·모듈·앱·저장소가 오는 경우) / 진행하 / 수행하 / 실시하 / 처리하 /
에 있어서 / 에 대한 / 을 필요로 / 에 위치한 / -들 (복수 표지) /
정확히 / 완전히 / 통째로 / 전부 / 바로 / 실제로 / 매우

마지막 줄의 강조 부사는 검색에 걸렸다고 지우는 것이 아니다. 4절의 삭제 검사를 먼저 통과시킨다 — 지워서 참·거짓이 안 변할 때만 지운다. 횟수나 범위를 한정하는 용법(`정확히 두 번 호출된다`)과 5절이 요구하는 확인 여부 표기(`실제로 재현했다`)는 남긴다.
