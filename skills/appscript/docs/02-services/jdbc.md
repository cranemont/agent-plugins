## 개요

`Jdbc`는 Apps Script에서 관계형 데이터베이스에 직접 SQL로 접속하는 서비스다. 표준 Java `java.sql` API를 얇게 감싼 것이라 클래스·메서드 이름이 JDBC 그대로다(`JdbcConnection`, `JdbcPreparedStatement` 등).

**지원 데이터베이스** (공식 가이드): Google Cloud SQL for MySQL, MySQL, Microsoft SQL Server, Oracle, PostgreSQL.

**언제 쓰는가**
- Sheets를 벗어나 실제 RDB에 읽기/쓰기를 해야 할 때
- Cloud SQL 인스턴스나 외부(온프레미스/타 클라우드) DB에 직접 쿼리할 때

**핵심 제약 두 가지** (공식 가이드 명시)
- JDBC 서비스는 **포트 1025 이상**에만 접속할 수 있다. DB가 그보다 낮은 포트로 서비스하면 안 된다.
- JDBC 연결은 **스크립트 실행이 끝나면 자동으로 닫힌다**. 다만 명시적으로 `close()` 하는 것을 권장한다.

## 연결 방식: Cloud SQL vs 외부 DB

진입점은 두 개이고, 대상 DB의 위치에 따라 선택한다.

| 구분 | `Jdbc.getCloudSqlConnection(url, ...)` | `Jdbc.getConnection(url, ...)` |
| --- | --- | --- |
| 대상 | Google **Cloud SQL for MySQL** | 그 외 모든 DB (외부 MySQL/SQL Server/Oracle/PostgreSQL). Cloud SQL도 IP로 접속 가능 |
| URL 형태 | `jdbc:google:mysql://<subname>` (`subname` = Cloud SQL **Instance Connection Name**) | `jdbc:mysql:<subname>` (외부 MySQL은 `jdbc:mysql://<HOST>:<PORT>/<DATABASE>`) |
| IP 대역 허용 | 불필요 (Google 내부 경로) | **필요** — DB 방화벽에서 Google 서버 IP 대역을 허용해야 함 |

Cloud SQL 접속 예:

```javascript
// Instance Connection Name = project:region:instance 형태
const conn = Jdbc.getCloudSqlConnection('jdbc:google:mysql://myproject:asia-northeast3:mydb/guestbook', user, pwd);
```

외부 MySQL 접속 예:

```javascript
const conn = Jdbc.getConnection('jdbc:mysql://203.0.113.10:3306/guestbook', user, pwd);
```

> **공식 Apps Script 문서엔 없음(벤더 규칙)**: 공식 JDBC 가이드·레퍼런스가 주는 URL 형태는 Cloud SQL용 `jdbc:google:mysql://<subname>` 와 MySQL용 `jdbc:mysql:<subname>` 둘뿐이다(2026-07-22 확인). **Microsoft SQL Server / Oracle의 JDBC URL 형식**(예: `jdbc:sqlserver://…`, `jdbc:oracle:thin:@…`)은 공식 Apps Script 문서에 없으므로 해당 DB 벤더의 JDBC URL 규칙을 따른다.

## Google 서버 IP 대역 허용 (외부 DB)

외부 DB는 Apps Script(=Google 서버)에서 오는 연결을 받아야 하므로, DB 쪽 방화벽/화이트리스트에 **Google 서버 IP 대역을 허용**해야 한다. 공식 가이드 원문: *"you must authorize IP ranges from this data source."*

공식 가이드는 **개별 IP 대역을 문서에 나열하지 않고**, 아래 정적 파일을 참조하도록 안내한다. IP 대역은 수시로 바뀌므로 이 파일을 원본으로 삼아야 한다.

| 대상 | 허용할 IP 대역 출처 |
| --- | --- |
| 일반 외부 DB (`getConnection`) | `https://www.gstatic.com/ipranges/goog.json` |
| Cloud SQL를 `getConnection`(IP)으로 접속 | `https://www.gstatic.com/ipranges/goog_ipv4_only.txt` |

> **변경 가능(수시 갱신)**: 위 파일의 IP 대역 목록은 Google이 수시로 갱신한다. 특정 IP를 문서/코드에 하드코딩하지 말고, 방화벽 규칙을 이 파일 기준으로 주기적으로 동기화하거나, 가능하면 Cloud SQL은 `getCloudSqlConnection`(IP 허용 불필요)으로 접속하는 편이 안전하다.

## 코드 예제

자격증명은 절대 하드코딩하지 않는다. 아래 예제는 모두 `PropertiesService`에서 접속 정보를 읽는다.

```javascript
// Script Properties: DB_URL, DB_USER, DB_PASSWORD 를 미리 저장해 둔다.
const P = PropertiesService.getScriptProperties();
const dbUrl = () => P.getProperty('DB_URL');
const dbUser = () => P.getProperty('DB_USER');
const dbPwd = () => P.getProperty('DB_PASSWORD');
```

### 1) 연결 → 쿼리 → ResultSet 순회

```javascript
function readEntries() {
  const conn = Jdbc.getCloudSqlConnection(dbUrl(), dbUser(), dbPwd());
  try {
    const stmt = conn.createStatement();
    stmt.setMaxRows(1000); // 방어적으로 상한을 건다
    const rs = stmt.executeQuery('SELECT id, guestName, content FROM entries');

    const rows = [];
    while (rs.next()) {
      rows.push({
        id: rs.getInt(1),               // 컬럼 인덱스는 1부터
        name: rs.getString('guestName'), // 라벨로도 조회 가능
        content: rs.getString('content'),
      });
    }
    rs.close();
    stmt.close();
    return rows;
  } finally {
    conn.close(); // 예외가 나도 반드시 닫는다
  }
}
```

### 2) PreparedStatement로 SQL 인젝션 방지

문자열을 직접 이어붙이지 말고 `?` 플레이스홀더 + `setXxx`로 값을 바인딩한다. 공식 가이드: *"To prevent SQL injection attacks, use parameterized statements to escape all user-supplied data."*

```javascript
function findByName(name) {
  const conn = Jdbc.getCloudSqlConnection(dbUrl(), dbUser(), dbPwd());
  try {
    // 나쁨:  "... WHERE guestName = '" + name + "'"  ← 인젝션 취약
    const ps = conn.prepareStatement('SELECT id, content FROM entries WHERE guestName = ?');
    ps.setString(1, name); // 값은 바인딩으로만
    const rs = ps.executeQuery();

    const out = [];
    while (rs.next()) out.push({ id: rs.getInt(1), content: rs.getString(2) });
    rs.close();
    ps.close();
    return out;
  } finally {
    conn.close();
  }
}
```

### 3) 배치 삽입 + 트랜잭션 (setAutoCommit / commit / rollback)

`setAutoCommit(false)`로 트랜잭션을 열고, `addBatch()`로 모아 `executeBatch()`로 한 번에 실행한 뒤 `commit()`. 실패하면 `rollback()`. 500건씩 배치로 쓰면 건별 `executeUpdate`보다 훨씬 빠르다.

```javascript
function insertEntries(entries) {
  const conn = Jdbc.getCloudSqlConnection(dbUrl(), dbUser(), dbPwd());
  conn.setAutoCommit(false); // 트랜잭션 시작
  const ps = conn.prepareStatement('INSERT INTO entries (guestName, content) VALUES (?, ?)');
  try {
    for (const e of entries) {
      ps.setString(1, e.name);
      ps.setString(2, e.content);
      ps.addBatch(); // 배치에 누적
    }
    const results = ps.executeBatch(); // 한 번에 실행
    conn.commit();                     // 전부 성공 시 커밋
    return results.length;
  } catch (err) {
    conn.rollback();                   // 하나라도 실패하면 전체 롤백
    throw err;
  } finally {
    ps.close();
    conn.close();
  }
}
```

> **참고 (공식 가이드의 "faster writes" 형태)**: 공식 JDBC 가이드는 위 `addBatch()`/인자 없는 `executeBatch()` 패턴과 함께, 값 배열을 직접 넘기는 `executeBatch(parameters)` 형태를 "Recommended for faster writes"로 제시한다(`const batch = stmt.executeBatch(params);`, `params`는 `params.push([...])`로 만든 행 배열). 이 오버로드는 `JdbcPreparedStatement` 레퍼런스 메서드 표에도 `executeBatch(parameters)` → `Integer[]`로 실제 기재돼 있다(표준 `java.sql`엔 없는 Apps Script 확장). 이식성 우선이면 표준 `addBatch()`, 성능 우선이면 `executeBatch(parameters)`.

### 4) getRows로 빠른 읽기

행 단위로 `next()`를 도는 대신, 조회할 게터를 한 번에 지정해 2차원 배열로 받는다. 왕복이 줄어 대량 읽기에 빠르다.

```javascript
function dumpEntries() {
  const conn = Jdbc.getCloudSqlConnection(dbUrl(), dbUser(), dbPwd());
  try {
    const stmt = conn.createStatement();
    stmt.setMaxRows(1000);
    const rs = stmt.executeQuery('SELECT * FROM entries');

    const numCols = rs.getMetaData().getColumnCount();
    const getters = [];
    for (let c = 1; c <= numCols; c++) getters.push(`getString(${c})`);

    const rows = rs.getRows(getters.join(',')); // Object[][]
    rs.close();
    stmt.close();
    return rows;
  } finally {
    conn.close();
  }
}
```

## 일반적인 패턴

### 자격증명은 PropertiesService

DB URL/계정/비밀번호는 코드가 아니라 `PropertiesService.getScriptProperties()`(또는 사용자별이면 `getUserProperties()`)에 둔다. 소스 공유·버전 관리·복제 시 자격증명이 새지 않는다. → `02-services/properties.md`

### try/finally로 반드시 close

Apps Script가 실행 종료 시 연결을 자동으로 닫아주긴 하지만, 오래 도는 스크립트에서 연결을 붙들고 있으면 하루 연결 쿼타를 빠르게 소진한다. `finally`에서 `close()`를 보장하라.

### 트랜잭션 경계 명확히

여러 쓰기가 원자적이어야 하면 `setAutoCommit(false)` → 작업 → `commit()`/`rollback()`로 감싼다. 부분 실패 지점만 되돌리려면 `setSavepoint()` / `rollback(savepoint)`를 쓴다.

### 6분 실행 한도 회피

대량 마이그레이션은 6분 실행 한도(→ `06-quotas/quotas-and-limits.md`)에 걸린다. 배치 크기·커서 위치를 `PropertiesService`에 저장하고 시간 기반 트리거로 이어서 처리하는 분할 실행 패턴을 쓴다.

## 주의사항 / Quota / 함정

### 연결 쿼타 (공식 quotas 페이지)

| 항목 | Consumer 계정 | Google Workspace 계정 |
| --- | --- | --- |
| JDBC 연결 수 / 일 | 10,000 | 50,000 |
| JDBC 실패한 연결 수 / 일 | 100 | 500 |

위 수치는 공식 quotas 페이지 기준이며 Google이 사전 공지 없이 변경할 수 있다. **동시 연결 수·연결 최대 수명 같은 JDBC 전용 한도는 공식 quotas 페이지에 없다**(2026-07-22 확인 — JDBC 항목은 위 "연결 수/일"·"실패한 연결 수/일" 두 행뿐). 단, 스크립트 실행 6분 제한과 일반 동시 실행 한도(사용자당 30)는 그대로 적용된다.

### 함정

1. **포트 1025 미만 접속 불가**
   JDBC 서비스는 포트 1025 이상만 연결한다. DB가 낮은 포트로 서비스하면 접속이 안 된다.

2. **외부 DB는 Google IP 허용 필수**
   방화벽에서 `goog.json`(또는 Cloud SQL IP 접속 시 `goog_ipv4_only.txt`) 대역을 허용하지 않으면 연결 실패로 잡힌다 — 실패 연결도 쿼타를 깎는다.

3. **자격증명 하드코딩 금지**
   URL/계정/비번은 `PropertiesService`로. SQL도 문자열 이어붙이기 대신 `PreparedStatement`로.

4. **컬럼 인덱스는 1부터**
   `getString(1)`, `setString(1, ...)`. 0부터가 아니다.

5. **연결/statement/resultSet 누수**
   자동 종료를 믿고 방치하면 하루 연결 쿼타를 금방 소진한다. `finally`에서 닫기.

6. **`executeBatch`는 두 형태가 모두 공식이다**
   인자 없는 `executeBatch()`(누적 `addBatch()` 실행)와 값 배열을 넘기는 `executeBatch(parameters)`가 둘 다 레퍼런스에 기재돼 있다. 후자는 가이드가 "faster writes"로 권장하는 Apps Script 확장으로 표준 `java.sql`엔 없다.

7. **JDBC 전용 OAuth 스코프는 명시 없음(별도 스코프 불요로 보임)**
   공식 가이드·레퍼런스·quotas 페이지 어디에도 JDBC 전용 OAuth 스코프가 없다(2026-07-22 확인). 별도 스코프 없이 동작하는 것으로 보이며, 필요 시 매니페스트 권한 동의 흐름에서 확인한다.

8. **SQL Server / Oracle URL 형식은 공식 문서에 없음(벤더 규칙)**
   공식 가이드·레퍼런스는 MySQL/Cloud SQL 형태만 준다. 타 벤더 URL 문자열은 벤더 JDBC 규칙을 따른다.
