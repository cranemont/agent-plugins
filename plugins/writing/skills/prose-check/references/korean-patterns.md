# 한국어 판정 절차와 실패 유형

`rules.md`의 한국어 고유 규칙(K1~K12)을 실제로 적용하는 방법이다. 본체는 낱말 목록이 아닌 **판정 절차**다.

1. 낱말을 지적받으면 그 낱말이 아니라 출처를 찾는다. 같은 출처에서 온 말이 더 있다.
2. 프로젝트에 자기 문체 규칙이 있으면, 그 프로젝트를 설명하는 글에도 그 규칙을 따른다.
3. 고치기로 했으면 파일 전체를 훑는다.

## 1. 절차가 본체인 이유

코드를 읽고 작성한 설명 글을 낱말 하나씩 고치면, 같은 문제가 다른 낱말로 다시 나온다. 흔한 순서는 이렇다.

| 고친 낱말 | 그 낱말이 생긴 원인 |
|---|---|
| entrypoint를 부른 `문`, 이어서 `문지기`·`방` | 코드에 없는 사물로 비유했다 (원인 A) |
| 무엇을 하는지 밝히지 않은 `센다` | 동작을 뭉갰다 (STE 3.7) |
| `낸다`·`잰다` | 코드 주석의 말투를 옮겼다 (원인 B) |
| 본문에서 고친 `짚다`가 그림에는 그대로 | 본문만 고쳤다 (원인 C) |
| `프로그램에 묻는다` | 다시 코드 주석의 말투를 옮겼다 (원인 B) |

낱말은 매번 다르지만 원인은 늘 2절의 원인에 속한다. 낱말을 지우는 것으로는 끝나지 않는다. 같은 출처에서 온 말이 더 있기 때문이다.

## 2. 세 가지 원인

| | 원인 | 증상 |
|---|---|---|
| A | 비유를 지어낸다 (K3) | 코드에 없는 사물이 글에 나온다: `문`·`문지기`·`상자`·`줄`·`손가락` |
| B | 코드 주석·ADR의 압축된 말투를 독자용 글에 옮긴다 (STE 1.10) | 그 코드를 아는 사람끼리 사용하는 말이 설명서에 나온다: `낸다`·`잰다`·`임자`·`동봉`·`1급` |
| C | 고칠 때 본문만 고친다 | 도형·표 머리·칩·`title` 속성에 그대로 있다 |

B가 가장 많고 가장 눈에 띄지 않는다. 코드를 읽고 작성한 글은 모두 **B의 위험**이 있다.

## 3. 네 질문 (K1)

의심스러운 명사·동사마다 차례로 묻는다. 하나라도 통과하지 못하면 바꾼다.

1. **출처**: 이 표현을 어디서 가져왔나? 코드 주석·ADR·타입 이름·커밋 메시지에서 복사했으면 나머지 질문 없이 바꾼다.
2. **화면**: 사용자가 보는 글자에 이 말이 있나? 기억으로 판단하지 않고 `grep`으로 확인한다. 화면이나 CLI 출력에 나오면 제품 용어이므로 그대로 사용한다. 주석·ADR·타입 이름에만 있으면 내부 말투이므로 바꾼다.
3. **역질문**: "○○가 뭐야?"에 비유 없이 한 문장으로 답할 수 있나? 답에 또 비유가 나오면 실패다. "문이 뭐야?"의 답이 "진입점"이면 처음부터 진입점이라고 작성한다.
4. **치환**: 그 낱말 대신 실제로 일어나는 일을 작성할 수 있나? 작성할 수 있으면 그것이 답이다. `낸다`는 만든다·돌려준다·기록한다·보여 준다 가운데 하나를 뜻한다. 하나를 고르지 못하면 그 코드를 아직 모르는 것이다. 글이 같은 일을 다른 낱말로도 부르고 있으면 하나로 맞춘다(STE 1.11).

```sh
# ② 화면 확인: 화면·CLI에 실제로 출력되는 문자열에 있나 (경로는 프로젝트에 맞게)
grep -rn '<말>' src/ --include='*.tsx' --include='*.ts' | grep -vE ':[0-9]+:[[:space:]]*(\*|//)'
```

## 4. 검사할 글인지 가른다

이 검사는 그 코드를 모르는 사람이 읽을 글에 적용한다.

| 늘 검사하는 글 | 요청이 있을 때만 검사하는 글 |
|---|---|
| 설명 문서·아티팩트·리포트 | 코드 주석·ADR·설계 메모 |
| README·가이드 | 타입·함수 이름 |
| 화면 문구·CLI 출력 | 내부 판정용 출력 |
| PR 본문·커밋 메시지 | |

오른쪽 칸은 일부러 압축해 작성한 글이다. 프로젝트 규칙이 그 글도 고치라고 하면 그 규칙을 따른다. 문제는 왼쪽 칸 글을 작성할 때 오른쪽 칸에서 말을 가져오는 것이다.

## 5. 손 검사

### 지어낸 비유 (K3)

글에서 명사를 모두 뽑아 코드에 있는 것과 대조한다. 코드에 없는 사물이 있으면 지어낸 것이다. 비유 하나를 사용하면 같은 계열의 비유가 늘어난다. `문`이라는 비유 뒤에 `문지기`·`방`·`옆방`이 더해졌다. 비유 하나를 지우면 그 계열 전체를 찾는다.

비유라고 표시한 곳은 괜찮다. 다만 거기서도 코드에 있는 것으로 비유한다.

### 영어 직역 동사 (K2)

물건이 움직이거나 놓이는 것처럼 작성한 동사다. 영어 lands·gets·stays·owns·slot을 옮긴 말이다.

| 있던 말 | 고치는 방향 |
|---|---|
| `자리` | 가리키는 것: 줄·파일·심볼·곳 |
| `받다` | 붙는다·차지한다·생긴다·읽는다 |
| `남다`·`남기다` | 하나뿐이다·보인다·그대로 둔다·기록한다 |
| `서다`·`세우다` | 나온다·만든다 |
| `맡다` | 정한다, 또는 무엇이 어디에 나오는지 |
| `가다`·`오다` | 분류한다·전송된다 |
| `떨어지다` | 사라진다·저장된다 |
| `들다` | 달린·속한·있는 |
| `걸다`·`걸리다` | 적용된다·일치한다 |
| `재다` | 계산한다·측정한다 |
| `박다` | 넣는다·고정한다·기록해 둔다 |
| `내다` | 만든다 |
| `닿다` | 호출을 따라가면 이른다 |
| `품다` | 안에 담는다 |
| "~은 넷이다" | 개수 문장을 지우고 목록만 작성한다 (K8) |

`영향받는`·`주고받는`·`기대다`·`보내다`, `시간이 걸린다`·`부하가 걸린다`처럼 한국어에 원래 있는 말은 그대로 둔다. `받는 사람`·`보낸 사람`은 수신자·발신자를 뜻하는 굳은 말이라 그대로 둔다. 자연스러운 표현을 고르지 못하면, 뜻과 작성하려던 문장을 보여 주고 사용자에게 묻는다.

### 직역투 문형 (K6)

| 문형 | 고치는 방향 |
|---|---|
| `~하는 것이 전부입니다` | 그것만 합니다 |
| `~에 답합니다` | ~를 알아냅니다 |
| `~인 것은 고장이 아닙니다` | ~는 정상입니다 |
| `이 그림에서 볼 것은 ~라는 점입니다` | 그 사실만 작성한다 |
| `~라는 판단이 앞에 있습니다` | ~기 때문입니다 |
| `~의 확대판입니다` | ~를 자세히 푼 것입니다 |
| `~을 통해` / `~에 의해` / `~에 대한 것` | 조사로 푼다 |
| `~에 대해서는` | ~에는 · ~은 |
| `~로부터` | ~에서 · ~에게서 |
| `~에 있어서` | ~에서 · ~은 · ~할 때 |
| `~를 가지고 있습니다` | ~가 있습니다 |

위 표의 `~을 통해`·`~에 의해`·`~에 대한 것`·`~에 대해서는`·`~로부터`·`~에 있어서` 줄은 사람이 작성한 기술 글에도 흔하다. 한 글에 여러 번 나와서 문장을 무겁게 할 때 고친다(검사 스크립트의 S2). 나머지 줄은 영어 문장 틀을 옮긴 것이라 한 번만 나와도 고친다. `결론적으로`·`요약하자면`은 담화 틀(K11)에서 다룬다.

`이 항목에 대해 묻습니다`처럼 `는` 없이 사용한 `~에 대해`는 그대로 둔다. 국립국어원은 `~에 대해서는`을 `~에는`으로 고친다.

`설정 파일이 저장소 안에 있어서`처럼 위치를 뜻하는 `있다`는 번역투가 아니다. 검사 스크립트는 `안`·`뒤`·`폴더` 같은 위치 낱말과 코드 스팬 뒤의 `~에 있어서`를 뺀다.

### 보조 용언 겹침 (STE 3.4)

`~하게 된다`·`~하게 됩니다`는 본동사로 줄인다. `지원하게 된다` → `지원한다`, `읽게 됩니다` → `읽습니다`. 상태가 바뀐 것이 요점이면 그대로 둔다. `이제 비공개 속성을 만들 수 있게 되었다`가 그 예다. `이렇게 됩니다`는 부사 뒤의 본동사라 대상이 아니다. 사람이 작성한 기술 글에도 흔해서 검사 스크립트가 S2로 찾는다.

### 뭉갠 동사 (STE 3.7)

`처리한다 · 수행한다 · 관리한다 · 담당한다 · 이용한다 · 적용한다 · 반영한다`는 무슨 일이 일어나는지 밝히지 않은 말이다. 함수 이름과 반환값을 확인하고 구체 동사로 바꾼다. `반영한다`는 사람이 작성한 기술 글에도 흔해서 검사 스크립트가 S2로 찾는다.

### 뜻이 갈리는 가벼운 동사 (STE 1.3)

`보다`·`나오다`·`되다` 같은 가벼운 동사는 문형마다 뜻이 다르다. 스크립트는 이 동사들을 낱말 후보로 뽑지 않는다. 다만 `보다`는 한 글에 두 뜻 이상이 나오면 파일 전체 후보로 보인다. 한 글에서 두 뜻 이상으로 사용하면 뜻마다 구체 동사로 바꾼다. 한 뜻으로만 사용하면 그대로 둔다.

| 문형 | 뜻 | 고치는 방향 |
|---|---|---|
| `판단을 봅니다` · `무엇을 보나` | 측정·평가 | `판단을 측정합니다` · `측정하는 것` |
| `낮은 수준으로 봅니다` | 간주 | `낮은 점수를 줍니다` · `낮은 단계로 판정합니다` |
| `평가할 수 있다고 봅니다` | 의견 | `평가할 수 있다고 정합니다` · `밝힙니다` |
| `운영 화면에서만 봅니다` | 열람 | `운영 화면에서만 볼 수 있습니다` |
| `나눠 보면` · `따져 봅니다` | 시도 (보조 용언) | 그대로 둔다 |

### 뜻이 둘인 동사: `쓰다`·`두다`·`잡다` (STE 1.3)

세 동사는 기술 글에서 두 뜻으로 나온다. 독자가 문장마다 뜻을 골라야 한다. 이 기준은 STE 1.3을 적용해서 이 플러그인이 정한 것이다. 스크립트가 활용형을 후보로 뽑는다. 한 글에 두 뜻이 함께 나오면 1.3 전체 후보("한 낱말 여러 뜻")로도 보인다.

| 동사 | 뜻 | 예 | 고치는 방향 |
|---|---|---|---|
| `쓰다` | 사용 | `버전 1.0을 쓴다` | `버전 1.0을 사용한다` |
| `쓰다` | 작성 | `코드에 쓴다` · `로그에 쓴다` | `코드에 작성한다` · `로그에 기록한다`. `적는다`는 구어체라 사용하지 않는다 |
| `두다` | 추가·설정 | `상한 검사를 둔다` · `임계값을 따로 둔다` | `상한 검사를 추가한다` · `임계값을 따로 설정한다` |
| `두다` | 유지 | `그대로 둔다` · `저장해 둔다` (보조 용언) | 그대로 둔다 |
| `잡다` | 설정 | `임계값을 높게 잡는다` | `임계값을 높게 정한다` · `설정한다` |
| `잡다` | catch | `예외를 잡는다` · `오류를 잡고` | 그대로 둔다 |

`쓰다`는 사용하지 않는다. `두다`는 유지 뜻으로만, `잡다`는 catch 뜻으로만 허용한다.

스크립트의 판별은 휴리스틱이다. `두다`는 `그대로 둔다`·`~게 둔다`와 보조 용언 `-아/-어 두다`(저장해 둔다)를 뺀다. 수사 `두 개`·`두어 번`과 `앞두다`·`그만두다`·`거두다`·`가두다`도 뺀다. 기본형 `두다`와 연결형 `두어야`·`두어서`는 후보다. `잡다`는 목적어가 예외·오류·에러·실패·버그·`Error`·`Exception`이거나 코드 스팬(`ApiError`)이면 뺀다.

`적다`는 목적어나 처소 뒤에 오는 활용형과 `적는다`·`적어 두다`·`적히다`만 찾는다. `적은 비용`·`적게`·`적어도`처럼 양이 적다는 뜻은 뺀다. 나머지 후보의 판정은 읽는 쪽이 한다.

후보에서 빼는 굳은 말: `덮어쓰다`·`글쓰기`·`띄어쓰기`·`붙여쓰기`·`받아쓰기`·`쓸모`·`쓸데없다`·`쓰임새`·`애쓰다`·`힘쓰다`·`신경 쓰다`·`마음 쓰다`·`읽기·쓰기`, `붙잡다`·`사로잡다`·`걷잡다`·`손잡이`·`자리 잡다`·`틀을 잡다`·`균형을 잡다`·`중심을 잡다`·`방향을 잡다`·`감을 잡다`·`초점을 잡다`·`잡음`·`잡다하다`. 수사 `두`·`둘`·`두어`(`두 개`·`둘 다`·`두어 번`)는 동사가 아니다.

### 높임 등급 (K9, STE 9.4)

본문은 높임 등급 하나로 작성한다. 등급은 프로젝트 규칙을 따르고, 규칙이 없으면 그 글에서 가장 많이 사용한 등급을 따른다. 제목·목록·표·인용은 본문과 따로 센다. 목록은 묶음마다 따로 센다.

| 본문 | 섞인 문장 | 판정 |
|---|---|---|
| 합쇼체 | 해라체 `서버를 다시 켠다.` | 고친다: `서버를 다시 켭니다.` |
| 합쇼체 | 해요체 서술 `캐시가 빨라졌어요.` · `~거든요` · `~죠` | 고친다: `캐시가 빨라졌습니다.` |
| 합쇼체 | 명령 `서버를 다시 시작하세요.` | 그대로 둔다. 한국어 기술 문서의 관례다 |
| 합쇼체 | 권유 `함께 바꿔 봅시다.` | 등급은 맞다. 다만 요약 예고(K11)인지 확인한다 |
| 해라체 | 합쇼체·해요체 문장 | 고친다 |
| 해요체 | 합쇼체 문장 | 프로젝트가 정한다. 정한 것이 없으면 해요체로 맞춘다 |
| 모든 등급 | 반말 `이건 캐시야.` | 고친다 |
| 모든 등급 | 명사형 `로그를 확인함.` | 본문이면 고친다. 목록과 표에서는 그대로 둔다 |

세지 않는 문장도 있다.

- 따옴표로 끝나는 문장: 남의 말을 옮긴 것이다. HTML의 `<blockquote>`·`<q>` 안의 글도 인용이다.
- 통째로 굵게 한 문장: 목록 머리의 이름표 구실을 한다. 이 문장은 형식(K12)에서 다룬다.
- `~인지`·`~할지`로 끝나는 조각: 물음을 담은 목록 항목의 형태다.
- HTML의 제목·표 칸·그림 설명·버튼 글자: 이름표다. 문단 속 조각도 문장 부호로 끝나지 않으면 세지 않는다. 대개 카드 제목이나 링크 글자다.

HTML에서는 블록 요소(`<p>`·`<div>` 등)마다 한 문단이다. 목록 묶음은 `<ul>`·`<ol>` 요소마다 정한다. 정의 목록에서는 `<dd>`마다 한 묶음이다. 한 정의 목록의 `<dd>`가 이유·조치·확인처럼 서로 다른 내용을 담기도 하기 때문이다.

한 문장 안에서 등급을 바꾸는 것은 더 나쁘다. 표 칸·라벨·도형 글자는 명사구나 `-ㄴ다`로 작성한다.

### 의문형 제목·라벨 (STE 9.4)

제목·표 머리·라벨을 해라체 의문형으로 작성하면 어색하다. 명사구로 바꾼다. 목록 항목이 물음이면 `~는지`로 바꾼다. 표 머리는 동사 꼴(`고쳐서`·`나오면`·`그대로 둔다`)로도 작성하지 않는다. `바꾼 말`·`있던 말`·`그대로 둘 문장`처럼 명사구로 작성한다.

| 있던 말 | 바꾼 말 |
|---|---|
| `무엇을 측정하나` · `무엇을 보나` (제목·표 머리) | `측정하는 것` · `○○의 정의` |
| `어디에 쓰나` | `쓰임새` |
| `왜 지금 ○○인가` | `지금 ○○이 필요한 이유` |
| `무엇이 뒷받침하나` (표 머리) | `근거` |
| `왜 이 길이인가` (표 머리) | `이 길이로 정한 이유` |
| `스스로 정하는가` (목록 항목) | `스스로 정하는지` |

독자가 실제로 묻는 질문(FAQ의 `~나요?`)은 그대로 둔다. 질문이 그 글의 내용이기 때문이다.

### 구어 형태 (K10)

말할 때만 사용하는 형태를 글말로 바꾼다. 등급이 맞아도 고친다.

| 있던 표현 | 고치는 방향 |
|---|---|
| `이건`·`그건`·`이게`·`그걸` | 가리키는 대상을 밝힌다: `이 값은`·`토큰 교환은` |
| `~는 건`·`~는 게`·`~할 거예요` | `~는 것은`·`~는 것이`·`~할 것입니다`, 또는 문장을 다시 작성한다 |
| `~거든요`·`~잖아요`·`~죠`·`~네요`·`~는데요` | `~기 때문입니다`·`~입니다` |
| `근데`·`그니까` | `그런데`·`그래서` |
| `되게`·`엄청`·`진짜` | 지우거나 수치로 바꾼다 |
| `좀`·`딱`·`그냥`·`살짝` | 지우거나 `조금`·`정확히`로 바꾼다 |
| 문장 첫머리 `사실`·`솔직히` | 지운다 |
| 감탄사 `아,`·`자,`·`음,` | 지운다 |

`한테`, `안`·`못`, `그런데`는 입말 낱말이지만 글말에서도 정상이다. 축약형을 풀 때 `-로부터`·`-에 있어서` 같은 책말로 바꾸지 않는다. 그러면 구어 형태는 사라져도 번역투가 생긴다.

인용과 대화 예시는 그대로 둔다. 원래 말이기 때문이다.

### 담화 틀 (K11)

내용을 더하지 않고 흐름만 끊는 틀이다. 영어 글의 틀을 옮겼거나 채팅 말투를 문서에 옮긴 것이다.

| 있던 표현 | 고치는 방향 |
|---|---|
| `단순히 X가 아니라 Y` · `X처럼 보이지만 실제로는 Y` | Y만 작성한다 |
| `이 값은 정체가 아니라 역할을 나타냅니다` | `이 값은 역할을 나타냅니다` |
| `핵심은 이겁니다:` · `결론부터:` | 예고 없이 내용을 작성한다 |
| `왜 그럴까요? 캐시가 오래됐기 때문입니다.` | `캐시가 오래되어 이 오류가 납니다.` |
| `결론적으로` · `요약하자면` · `정리하자면` | 지운다. 요점은 문단 첫 문장에 작성한다(K4) |
| `이제 ○○을 알아보겠습니다` · `앞서 설명했듯이` | 지운다 |
| `좋은 질문입니다` · `도움이 되었으면 합니다` | 지운다 |

독자의 오해를 바로잡는 대비는 그대로 둔다. 예를 들어 독자가 버그를 의심할 때 `코드 버그가 아니라 데이터 문제입니다`는 정보를 준다. 독자에게 실제로 묻는 말(`이 설정으로 진행할까요?`)도 자문자답이 아니다.

### 형식 (K12)

| 있던 형식 | 고치는 방향 |
|---|---|
| 문장 전체를 `**굵게**`(HTML은 `<strong>`·`<b>`) 함 | 굵게를 풀거나, 가장 중요한 낱말 하나만 굵게 한다 |
| 한 문단에 굵은 문장이 여럿 | 가장 중요한 하나만 굵게 둔다 |
| 본문의 `— 삽입구 —` · `A — B` · HTML `&mdash;` | 괄호를 사용하거나 문장을 나눈다 |

표 칸을 혼자 채운 줄표(`| — |`·`<td>—</td>`)는 빈 칸 표시라 그대로 둔다. 제목 줄의 줄표(`## 2단계 — 분류`)와 뒤에 영어 글이 오는 줄표(`**견고함** — what the user knows`)는 이 규칙 밖이다.

### 소리 내어 읽기

한 문단을 소리 내어 읽어 숨이 막히면 문장이 길거나 번역투다.

## 6. 오탐: 낱말 자체는 잘못이 없다

목록의 낱말이 그 문장에서 사실이고 아래 두 조건을 모두 채우면 그대로 둔다. 문제가 되는 것은 **뭉개는 용법**이다.

1. 더 정확한 말이 없다. 네 질문의 ④ 치환으로 확인한다.
2. 글이 같은 일을 다른 낱말로 부르지 않는다(STE 1.11). 둘째 조건을 건너뛰면, 같은 일을 두 낱말로 부르는 글을 그대로 통과시킨다.

| 그대로 둘 문장 | 바꿀 문장 |
|---|---|
| `완결된 달만 셉니다`. 달을 실제로 헤아린다 | `분석기가 재고를 센다`. 무엇을 하는지 밝히지 않았다 |
| `멤버 수를 세어 온다` | `차례와 수치를 코드가 셉니다` |
| `삭제한 줄을 재서 붙인다` | `분석기가 재는 것` |
| `줄 길이를 잰다`. 글에 `측정`이 없다 | `재려는 능력`. 같은 글에 `측정하려는 능력`도 있다 |
| `countDocuments로 문서 수를 센다` · `원본 강의가 없는 챌린지를 센다`. SQL `count`가 실제로 센다 | `도구가 센 후보`. 도구가 찾아 둔 후보다 |
| `사용자에게 알리고 동의를 받는다` | `행이 카드를 받는다` |
| `SQS 큐 9개에 오래된 메시지가 남아 있음`. 큐에 메시지가 실제로 있다 | `결과가 캐시에 남는다`. 저장한다 |

판정은 네 질문의 ④ 치환이 한다. 더 구체적인 동사를 넣을 수 있으면 뭉갠 것이고, 더 정확한 말이 없으면 그 말이 맞다. 스크립트가 뽑은 후보를 모두 고치면 맞는 글을 망친다.

스크립트는 `문서 수를 센다`처럼 목적어가 수인 꼴만 뺀다. `챌린지를 센다`·`메시지가 남아 있음`은 낱말만으로 가를 수 없다. 스크립트는 이것을 후보로 보고한다.

프로젝트가 자기 분야에서 늘 사용하는 사실 표현은 저장소 최상위의 `.prose-check-allow`에 작성한다. 한 줄에 한 글귀다. 글귀는 두 어절 이상이고, `#` 뒤는 주석이다. 스크립트는 그 글귀 안의 낱말 후보를 빼고, 뺀 수를 보인다. 위 두 조건을 통과한 표현만 작성하고, 그 문장도 검토 때 읽는다. 목록은 판정의 기록이지 규칙이 아니다.

## 7. 고칠 때 (STE 9.1, K7)

낱말만 바꾸면 비문이 된다. 예를 들면 이렇다.

| 적용한 규칙 | 나온 글 |
|---|---|
| `임자` → `맡는 곳` | `어휘의 맡는 곳도 옮겼다` (조사가 안 맞는다) |
| `동봉` → `옆에 같이 붙인다` | `옆에 옆에 같이 붙인다` (앞말과 겹친다) |
| `장` → `섹션` | `문섹션` · `주섹션` (낱말 안쪽을 건드렸다) |

그래서 바꾸는 규칙은 앞뒤 조사까지 작성한다. `임자가 하나다` → `처리할 함수가 하나다`처럼 작성한다. 고친 뒤에는 diff에서 깨진 곳을 찾는다.

```sh
git diff | grep '^+' | grep -E '(곳를|곳가|옆에 옆에)'   # 겹친 말·깨진 조사
git diff | grep '^+' | grep '  '                         # 이중 공백
```

짧은 낱말은 다른 낱말 안에 들어 있다. `장`은 문장·주장·저장·확장·등장 안에 있다. 바꾸기 전에 전체 횟수와, 낱말 하나로 나온 횟수를 센다. `grep -c`는 줄 수를 세므로 한 줄에 `장`과 `문장`이 같이 있으면 틀린다. `grep -o`로 출현마다 센다. 두 수가 다르면 그 규칙은 일괄로 적용할 수 없다.

```sh
grep -o '장' 문서.md | wc -l                                                   # 전체 횟수: 문장·저장 안의 것도 센다
grep -oE '(^|[^가-힣])장([은는이가을를의에도로와과만]|[^가-힣]|$)' 문서.md | wc -l   # 낱말 하나로 나온 횟수: 앞은 한글이 아니고, 뒤는 조사이거나 한글이 아니다
```

코드 파일은 주석 안에서만 고친다. 문자열 리터럴을 건드리면 화면 글자와 테스트가 깨진다.

## 8. 전체 훑기와 계열 찾기

- **전체 훑기 (원인 C).** 낱말 하나를 고치기로 했으면 그 글자를 파일 전체에서 찾는다. 놓치기 쉬운 곳은 SVG `<text>`, 표 머리, 칩·버튼 라벨, `title`·`alt`·`aria-label`, 범례, 그림 설명, 목차다.
- **계열 찾기 (원인 B).** 지적받은 낱말이 코드 주석에서 왔다면, 같은 주석에서 온 말이 더 있다. 그 주석을 다시 읽고 옮긴 말을 모두 뽑는다.
- **다른 이름 찾기 (STE 1.11).** 낱말 하나를 바꾸기로 했으면, 같은 일을 가리키는 다른 낱말도 글에서 찾는다. `재다`를 고치면 `측정`이, `가다`(전송)를 고치면 `보내다`·`전달`이 같은 글에 있는지 확인한다. 있으면 하나로 맞춘다.

## 9. 코드 주석에서 옮겨 오기 쉬운 말

이 표는 규칙이 아니라 예다. 다음 실수는 이 표에 없는 낱말에서 나온다.

| 있던 말 | 바꾼 말 |
|---|---|
| `바깥에서 오는 문` · `문지기` | `진입점` · `서버가 검사한다` |
| `손가락으로 짚어 간다` | `식별자를 따라간다` |
| `재고를 센다` · `도구가 센 후보` | `코드를 읽는다` · `도구가 찾아 둔 후보` |
| `냅니다` · `내놓아` · `내주고` | `만듭니다` · `넘겨줘서` · `알려 주고` |
| `잰다` · `쟀다` | `알아낸다` · `대조했다` |
| `임자` | `어느 층` · `처리할 함수` |
| `도는 코드` · `안 도는 선언` | `실행되는 코드` · `호출되지 않는 선언` |
| `~에 삽니다` · `한 벌이 더 산다` | `들어 있습니다` · `하나를 더 추가합니다` |
| `짚을 것` | `미리 알아둘 것` |
| `변경이 앉은 자리` | `변경을 감싸는 선언` |
| `계약에 싣는` | `계약에 담는` |
| `프로그램에 묻는` | `프로그램에서 찾아오는` |
| `1급 단위` · `무주공산` · `유일한 표면` | `기본 단위` · `가리키는 곳 없음` · `유일한 입구` |
| `예산 9행` · `위임 3겹` | `최대 9행` · `위임 3단계까지` |
| `로그를 찍는다` · `콘솔에 찍힌다` | `로그를 출력한다` · `콘솔에 출력된다` |

화면이나 CLI에 실제로 출력되는 글자는 바꾸지 않는다. 바꾸면 글과 화면이 대조되지 않는다.

## 10. 목록 갱신과 정밀도

낱말 목록은 지난 실수의 기록이라 모델이 바뀌면 낡는다. 그래서 아래 측정을 정기적으로 한다.

1. **과대 출현 측정.** `excess.mjs`가 AI 출력과 사람 글의 형태소 빈도를 비교한다. 사람 쪽은 `baseline.tsv`이고, 2022-11-30 이전에 나온 한국어 기술 글로 만들었다. 배율과 G²가 높은 말을 읽고, 주제 차이로 올라온 말은 버린다. 같은 습관에서 나온 말을 묶어 `check.mjs`의 규칙과 이 파일의 표에 더한다.
2. **정밀도 측정.** `check.mjs --tsv=판정.tsv`로 후보를 표로 저장하고, label 칸에 `y`(맞는 지적)와 `n`(오탐)을 채운다. `precision.mjs 판정.tsv`가 규칙별 정밀도를 계산한다. 오탐이 10%를 넘는 규칙은 S2로 내리거나 뺀다.
3. **탐지율 측정(검증 루프).** `pairs.mjs`가 국립국어원이 고친 문장 쌍(`pairs/style.tsv`)에 검사 스크립트를 돌린다. 고치기 전 문장에서 찾은 쌍의 수와, 고친 뒤 문장에 나온 후보를 보인다. 그리고 저장한 기준(`pairs/results.json`)과 비교한다.
   - 전에 찾던 쌍을 놓치거나, 고친 뒤 문장에 새 후보가 나오면 실패한다(종료 코드 1).
   - `--human`은 사람 글 말뭉치의 1,000어절당 후보 수도 측정한다. 후보가 늘어난 규칙은 2번으로 정밀도를 판정한다.
   - 결과가 나아졌고 정밀도도 확인했으면 `--save`로 기준을 갱신한다.

관리 도구는 설치한 스킬에 들어가지 않는다. 원본 저장소의 `scripts/prose-check/`에 있고, 저장소 최상위에서 실행한다.

```sh
node scripts/prose-check/excess.mjs --model=<모델 이름> --since=<날짜> --examples   # 대화 기록에서 후보 찾기
node scripts/prose-check/excess.mjs --under                                     # 사람 글에 더 흔한 말 (S2로 내릴 근거)
node plugins/writing/skills/prose-check/scripts/check.mjs --tsv=판정.tsv <글...>  # 판정 표 만들기
node scripts/prose-check/precision.mjs 판정.tsv                                   # 규칙별 정밀도
```
