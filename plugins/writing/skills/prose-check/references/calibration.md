# 문장 길이 기준의 측정

`rules.md` 4절의 12·15어절 기준이 맞는지 측정한 기록이다. 측정일은 2026-10-07이다.

## 1. 무엇을 확인했나

STE의 문장 길이 기준은 영어 단어 수다. 한국어에 적용하려면 같은 내용의 한국어 어절 수가 영어 단어 수의 몇 배인지 알아야 한다. 이 스킬은 그 비율을 60% 안팎으로 보고 20·25단어를 12·15어절로 옮겼다. 이 문서는 그 비율을 측정한다.

## 2. 방법

1. ASD-STE100 Issue 9 공식 PDF의 Part 1(44~125쪽)에서 `STE:` 표지가 붙은 예문을 뽑았다. 217문장이 나왔다.
2. 영어 낱말 자체를 설명하는 문장은 뺐다. 승인 낱말·품사·문장 규칙을 말하는 문장이다. 목록·표·제목이 섞인 조각도 뺐다.
3. 남은 문장에서 길이 구간마다 고르게 43문장을 골랐다.
4. 표본을 만들 때 부품 번호 괄호(`(10)` 등)는 영어·한국어 양쪽에서 미리 지웠다. 그래서 `calibration.tsv`에는 괄호가 없다. 한국어에서는 괄호를 보통 명사에 붙여서 작성하기 때문에 셈이 틀어진다.
5. 각 문장을 자연스러운 기술 한국어로 옮겼다. `rules.md`의 한국어 규칙을 지키고, 뜻을 줄이거나 덧붙이지 않았다.
6. 영어는 STE 8.5·8.7로 셌다. 괄호 안 글은 한 단어다. 한국어는 `check.mjs`와 같은 방식으로 셌다. 코드 스팬은 한 어절이고, 인용 괄호(ADR·조항·날짜·커밋)만 세지 않는다. 다른 괄호는 그대로 센다.

데이터는 `calibration.tsv`, 측정 스크립트는 `calibrate.mjs`다. 둘 다 원본 저장소의 `scripts/prose-check/`에 있고, 설치한 스킬에는 들어가지 않는다. 저장소 최상위에서 실행한다.

```sh
node scripts/prose-check/calibrate.mjs                    # 기본 데이터
node scripts/prose-check/calibrate.mjs 다른표본.tsv        # 열: page, en, ko
```

## 3. 결과

| 항목 | 값 |
|---|---|
| 표본 | 43문장, 영어 567단어, 한국어 352어절 |
| 합계 비율 | 0.621 |
| 문장별 중앙값 | 0.625 |
| 문장별 사분위 | 0.571~0.667 |
| 문장별 범위 | 0.429~0.875 |
| 회귀식 | 한국어 = 0.549 × 영어 + 0.94 |
| 영어 20단어 | 회귀 11.9어절, 합계 비율 12.4어절 |
| 영어 25단어 | 회귀 14.7어절, 합계 비율 15.5어절 |

| 영어 길이 | 문장 | 비율 |
|---|---|---|
| 1~10단어 | 10 | 0.662 |
| 11~15단어 | 18 | 0.631 |
| 16~20단어 | 15 | 0.600 |

12·15어절 기준은 측정과 맞는다. ADR의 60% 추정은 0.62로 확인됐다. 긴 문장일수록 비율이 조금 낮아진다. 그래서 회귀식이 합계 비율보다 기준값에 더 가깝다.

## 4. 한계

- **사람 번역이 없다.** 한국어는 Claude가 옮겼다. 사람 번역은 어절이 더 많거나 적을 수 있다.
- **분야가 다르다.** 예문은 항공 정비 문서다. 소프트웨어 설명 문서에서는 영어 식별자가 많아 비율이 달라질 수 있다.
- **25단어 구간은 외삽이다.** STE 예문은 짧아서 21단어 넘는 깨끗한 문장이 없었다. 25단어 환산은 20단어까지의 추세를 늘린 값이다.
- **표본이 작다.** 43문장이다. 문장별 비율의 범위가 0.43~0.88로 넓다. 문장 하나에 이 비율을 적용해 판정하지 않는다. 기준은 후보를 뽑는 데만 사용한다.

## 5. 다시 측정하는 법

1. `calibration.tsv`의 `ko` 열을 사람 번역으로 바꾸거나, 새 표본 파일을 만든다.
2. `node scripts/prose-check/calibrate.mjs <파일>`을 돌린다.
3. 회귀값이 12·15에서 한 어절 넘게 벗어나면 `rules.md` 4절과 `check.mjs`의 기준값을 함께 고친다.
